# WireMock for local setup

WireMock (`wiremock/wiremock:3.13.2`, host port 8083) has two jobs:

- **Mock services for admin-service.** `../mosip-config/admin-local.properties` points the IAM (Keycloak / authmanager), auditmanager, WebSub hub, regproc, packet receiver, idrepo and digitalcard URLs at `http://localhost:8083`. Keymanager is not mocked; it runs for real.
- **Gateway for the API test rig.** The rig's environment endpoint is `http://localhost:8083`. WireMock answers its login and setup calls and forwards its masterdata and admin API calls to admin-service on the host.

At start, WireMock reads every file in `mappings/` (mounted read-only) and merges all stubs into **one list**.

## The mapping files

Each file holds the stubs for one caller: who sends the request to WireMock decides the file, not who needs the answer.

| File | Caller | Edit? |
|---|---|---|
| `mappings/keycloak-authmanager.json` | admin-service and the API test rig (tokens and token checks) | No: generated by `tools/jwt` from `tools/jwt/tokens.properties` (`./run-local-stack.sh tokens`) |
| `mappings/admin-services.json` | admin-service (services it calls) | Yes |
| `mappings/api-test-rig.json` | API test rig (gateway and rig setup calls) | Yes |

### `keycloak-authmanager.json` (generated)

| Stub | Request | Response |
|---|---|---|
| `iam-jwks` | `GET /auth/realms/*/protocol/openid-connect/certs` | Public key admin-service uses to verify tokens |
| `iam-client-<client>` | `POST /v1/authmanager/authenticate/clientidsecretkey`, matched on `clientId` in the body | Client token |
| `iam-oidc-token-<client>` | `POST /auth/realms/*/protocol/openid-connect/token`, matched on `client_id` in the body | Client token |
| `iam-oidc-token-basic-<client>` | Same URL, matched on the client in the HTTP Basic auth header (Keycloak admin client) | Client token |
| `iam-user-<user>`, `iam-user-internal-<user>` | `POST /v1/authmanager/authenticate/[internal/]useridPwd`, matched on `userName` | User token |

One set per client and user in `tokens.properties`. An unknown user or client gets a 404.

### `admin-services.json` (services admin-service calls)

| Stub | Request | Response |
|---|---|---|
| `auditmanager-audits` | `POST /v1/auditmanager/audits` | Success |
| `authmanager-userdetails` | `/v1/authmanager/userdetails…` | User details |
| `websub-hub` | `/hub` | Success |
| `regproc-workflow-search-empty-column`, `regproc-workflow-search-invalid-pagination` | `POST /registrationprocessor/v1/workflowmanager/workflow/search`, matched on the body | regproc errors `RPR-WAA-000` / `RPR-WAA-002` |
| `regproc-workflow-action-unknown-id` | `POST /registrationprocessor/v1/workflowmanager/workflowaction` | regproc error `RPR-WAA-003` |
| `actuator-health` | `GET /<any service>/actuator/health` | `{"status":"UP"}` |
| `regproc-and-packet-receiver` | anything under `/registrationprocessor/v1/` | Generic success (catch-all) |
| `idrepo-identity` | anything under `/idrepository/v1/` | Generic success (catch-all) |
| `digitalcard` | anything under `/v1/digitalcard` | Generic success (catch-all) |

### `api-test-rig.json` (API test rig)

| Stub | Request | Response |
|---|---|---|
| `gateway-masterdata` | anything under `/v1/masterdata/` | Proxied to admin-service: `http://host.docker.internal:8086` |
| `gateway-admin` | anything under `/v1/admin/` | Proxied to admin-service: `http://host.docker.internal:8086` |
| `keycloak-admin-users-search` | `GET /auth/admin/realms/mosip/users` | `[]` |
| `keycloak-admin-users-create` | `POST /auth/admin/realms/mosip/users` | `409`, which the rig treats as "user exists" |
| `regproc-actuator-env` | `GET /registrationprocessor/v1/registrationtransaction/actuator/env` | regproc's age-group setting, read by the rig |

## Priority order (works across all files)

When a request matches several stubs, the stub with the **lowest priority number** answers. A stub without a priority counts as 5. Because WireMock merges all files into one list, **priorities compete across files**: a stub in one file can be hidden by a catch-all in another.

| Priority | Used for | Stubs |
|---|---|---|
| 1 | JWKS and tokens matched on the body | `iam-jwks`, `iam-client-*`, `iam-oidc-token-*`, `iam-user-*` |
| 2 | Tokens matched on Basic auth | `iam-oidc-token-basic-*` |
| 3 | Specific error responses | `regproc-workflow-*` |
| 4 | Specific responses inside a catch-all's range | `regproc-actuator-env` |
| 5 (default) | Normal stubs and the gateway | auditmanager, userdetails, WebSub hub, Keycloak admin, `gateway-*` |
| 9 | Health of any service | `actuator-health` |
| 10 | Catch-alls for a whole service | `regproc-and-packet-receiver`, `idrepo-identity`, `digitalcard` |

Examples:

- `GET /registrationprocessor/v1/registrationtransaction/actuator/env` matches `regproc-actuator-env` (4, rig file) and the regproc catch-all (10, `admin-services.json`). The rig stub answers.
- `GET /registrationprocessor/v1/.../actuator/health` matches `actuator-health` (9) and the regproc catch-all (10). The health stub answers.

**When adding a stub:** check all three files for a stub whose URL also matches yours. If one exists, give yours a lower number than it (3 for an error case, 4 for any other specific response inside a catch-all). Never give a catch-all a number below 10.

## Changing the admin-service port for the API test rig

The gateway stubs forward to admin-service on port **8086**. If admin-service runs on another port (for example 8096 with `./run-local-stack.sh run 8096`) and the rig should test that instance:

1. In `mappings/api-test-rig.json`, change `proxyBaseUrl` in **both** `gateway-masterdata` and `gateway-admin`, for example to `http://host.docker.internal:8096`.
2. Reload: `curl -X POST http://localhost:8083/__admin/mappings/reset`.
3. Check: `./run-local-stack.sh smoke 8096`, then run the rig.

The rig settings themselves do not change: the rig always talks to WireMock on 8083. Set the port back to 8086 before committing.

## Removing the gateway stubs (future)

The gateway stubs exist only because the rig's per-service base URLs (`mosip_components_base_urls`) work only for `https://` endpoints in `apitest-commons` 1.3.3. Once a released `apitest-commons` also handles `http://`:

1. Delete `gateway-masterdata` and `gateway-admin` from `mappings/api-test-rig.json`. Keep the other rig stubs (Keycloak admin, regproc `actuator/env`).
2. Run the rig with `mosip_components_base_urls=masterdata=localhost:8086;admin=localhost:8086` and `moduleNamePattern=(masterdata|admin)` (unless the release already knows `admin`), and update the rig settings in the main `README.md`.
3. Remove the "Changing the admin-service port" section above; the port then comes from `mosip_components_base_urls`.

## Adding or changing a stub

1. Find the request that has no stub: `curl -s http://localhost:8083/__admin/requests/unmatched`.
2. Pick the file by caller (see "The mapping files") and the priority (see "Priority order").
3. Add the stub, for example:
   ```json
   {
     "name": "auditmanager-audits",
     "priority": 5,
     "request": { "method": "POST", "urlPathPattern": "/v1/auditmanager/audits" },
     "response": {
       "status": 200,
       "headers": { "Content-Type": "application/json" },
       "jsonBody": { "id": "mosip.local.stub", "version": "v1", "responsetime": "2026-01-01T00:00:00.000Z",
                     "metadata": null, "response": { "status": true }, "errors": null }
     }
   }
   ```
4. Check the file is valid JSON: `python3 -m json.tool deps/wiremock/mappings/<file>.json > /dev/null`.
5. Reload: `curl -X POST http://localhost:8083/__admin/mappings/reset`.
6. Repeat the request, then run `./run-local-stack.sh smoke`.

## Rules

- Never edit `keycloak-authmanager.json`. Change `tools/jwt/tokens.properties` and run `./run-local-stack.sh tokens`.
- Put a stub in the file of the caller that sends the request (see "The mapping files").
- Check priorities across all three files before adding a stub (see "Priority order"). Give every stub a unique `name`.
- Responses use the MOSIP response shape (`id`, `version`, `responsetime`, `response`, `errors`); error stubs use the real service's error codes.
- Every file must be valid JSON: WireMock exits at start (`MappingFileException`) if one is not.
- No real data, tokens or secrets from any environment.
- Keep the image pinned to a version in `../docker-compose.yml`.

## Keeping the mappings up to date

The mapping files have no upstream copy; they follow what admin-service and the rig call.

- admin-service calls a new service or endpoint: add a stub to `admin-services.json`.
- A service's responses or error codes change: update its stub to match the service's current release.
- Users, clients or roles change: edit `tools/jwt/tokens.properties`, then `./run-local-stack.sh tokens`.
- The API test rig makes a new outside call: add a stub to `api-test-rig.json`, then run the rig.
- New WireMock version: change the tag in `../docker-compose.yml`, run `./run-local-stack.sh up`, then `smoke` and the rig.
