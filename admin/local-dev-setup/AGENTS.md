# AGENTS.md

This file provides guidance to AI agents when working with code in `admin/local-dev-setup`.

## What This Setup Is

Runs, debugs and tests admin-service on a developer machine without a MOSIP cluster. admin-service runs on the host (IDE or jar); its dependencies run in Docker (compose project `admin-local`).

- Real: PostgreSQL (`mosip_master`, `mosip_keymgr`), config server, keymanager.
- Mocked: WireMock for the IAM (Keycloak / authmanager) and the other MOSIP services; it is also the API test rig's gateway.
- Fresh database from the repo's `db_scripts` plus sample test data; tokens pre-generated.
- Checked by `smoke` and the masterdata API test rig.

How-to for humans: `README.md`. Per-folder rules and refresh steps: the `README.md` in each folder under `deps/` and `tools/jwt/`.

## Ports

| Port | Component | Notes |
|---|---|---|
| 8086 | admin-service | On the host (IDE or jar). Run with `-Dspring.profiles.active=default,local`. A second instance uses 8096 (`run 8096`) |
| 51200 | config-server | `http://localhost:51200/config` (51000 inside the container) |
| 5456 | PostgreSQL | `mosip_master` (`masteruser`), `mosip_keymgr` (`keymgruser`); password `mosip123` |
| 8083 | WireMock | IAM and other-service stubs; API test rig gateway |
| 8089 | keymanager | Real, PKCS12 keystore, no token check |

## Local configuration

**Config served by the config server** (`deps/mosip-config/`)

| File | Purpose | Edit? |
|---|---|---|
| `admin-local.properties` | admin-service overlay: all local changes | Yes |
| `keymanager-local.properties` | keymanager overlay | Yes |
| `*-default.properties`, `identity-mapping.json`, `applicanttype.mvel` | Verbatim `mosip-config` copies | No |

**Stack and database**

| File | Purpose | Edit? |
|---|---|---|
| `deps/docker-compose.yml` | Containers, ports, pinned images, volumes | Yes |
| `deps/init.sql` | Builds `mosip_master` from `../../db_scripts`, then `mosip_keymgr` from `keymanager/db_scripts` | Yes |
| `deps/keymanager/db_scripts/mosip_keymgr/` | Verbatim keymanager `db_scripts`, tag `v1.4.1` (same as the image) | No |
| `deps/keymanager/bootstrap.sh` | keymanager entrypoint; creates `ROOT`, `KERNEL`, `KERNEL:SIGN` | Yes |
| `deps/mosip-data/xlsx/` | Sample test data, verbatim `mosip-data` copy | No |
| Docker volumes `admin-local_postgres-data`, `admin-local_keymanager-keys` | Database and keystore (not in the tree) | Reset with `wipe` only |

**WireMock and tokens**

| File | Purpose | Edit? |
|---|---|---|
| `deps/wiremock/mappings/admin-services.json` | Stubs for the services admin-service calls | Yes |
| `deps/wiremock/mappings/api-test-rig.json` | `/v1/masterdata` and `/v1/admin` proxied to the host app; Keycloak admin and regproc actuator stubs | Yes |
| `deps/wiremock/mappings/keycloak-authmanager.json` | IAM stubs, generated by `tools/jwt`; committed | No: run `tokens` |
| `tools/jwt/tokens.properties` | Users, clients, roles, issuer, kid, validity | Yes |
| `keys/jwt-signing-key.pem` | JWT signing key, created by the first `tokens` run; gitignored | No |

## Script (`run-local-stack.sh` / `.bat`)

```text
up (default)   start the 4 containers (after the one-off keymanager-keys-init), wait healthy; load sample test data if master.zone is empty
down           remove the containers; DB and keystore volumes kept
wipe           down -v (both volumes), then up (fresh DB, new keys, sample test data)
status         container status
logs [svc]     follow logs (default keymanager)
tokens         regenerate the WireMock IAM tokens, reload WireMock
build          mvn -pl admin-service -am package -DskipTests -Dgpg.skip=true
run [port]     run the jar against the stack (default 8086)
smoke [port]   4 dependency checks, login, 6 app checks (health, auth on/off, admin API, sample test data, keymanager proxy)
help           list commands
```

## Verifying a change (agent flow)

| Instance | Port | Owner | Rule |
|---|---|---|---|
| IDE run | 8086 | the user | Never stop or restart it. IDE setup and VM options: `README.md`, "Run" |
| Agent run | 8096 | the agent | Start it for the check, stop it when done |

All commands run from `admin/local-dev-setup/`.

### 1. Check the stack

```bash
./run-local-stack.sh status
```

- All four containers `healthy`: go on.
- A container missing or not `healthy`: `./run-local-stack.sh up`.
- Never run `down` or `wipe` unless the user asks. `wipe` deletes the database and the keys.

### 2. Build and test

```bash
./run-local-stack.sh build                      # must end with BUILD SUCCESS
(cd ../admin-service && mvn test)               # for code changes
```

Skip this step for a config-only change (an overlay in `deps/mosip-config/`).

### 3. Start the agent instance

```bash
./run-local-stack.sh run 8096 > <log> 2>&1 &
```

Watch `<log>`, not a fixed sleep (start-up takes about 10 s):

| Log line | Meaning |
|---|---|
| `Started AdminBootApplication` | Ready, go to step 4 |
| `APPLICATION FAILED TO START` | Start-up failed; read the log above it |
| `Could not resolve placeholder` | A value is missing from `admin-local.properties` |
| `Port 8096 was already in use` | An earlier agent instance is still running; stop it first |

### 4. Check the instance

```bash
./run-local-stack.sh smoke 8096                 # every line [ OK ], then "All smoke checks passed"
```

Then call the endpoints the change touches on `http://localhost:8096`, with a token (see "Get a token" in `tools/jwt/README.md`).

### 5. API test rig

Run the rig that covers the APIs the change touches. The settings for humans (IDE run configuration) are in `README.md`, "API test rig".

| Rig | Covers | Runner class | `-Dmodules` |
|---|---|---|---|
| masterdata | `/v1/masterdata/**`, `/v1/admin/**` | `io.mosip.testrig.apirig.masterdata.testrunner.MosipTestRunner` | `masterdata` |

How a rig reaches the app:

```text
rig ──► WireMock :8083 (env.endpoint) ──► gateway stubs (deps/wiremock/mappings/api-test-rig.json) ──► admin-service :8086
```

1. **Point the gateway at 8096**, as in `deps/wiremock/README.md` ("Changing the admin-service port").
2. **Build the rig once**, in the rig's `api-test` folder:
   ```bash
   mvn -q package -DskipTests
   mvn -q dependency:build-classpath -Dmdep.outputFile=target/cp.txt
   ```
3. **Run the rig in the background** from the same `api-test` folder, in bash (macOS, Linux, or Git Bash on Windows). The command below runs the masterdata rig.
   - Another rig: change the runner class and `-Dmodules` (see the table above).
   - `env` passes the rig settings, because names such as `keycloak-external-url` cannot be set with normal shell syntax.
   - The first line picks the classpath separator: `:` on macOS and Linux, `;` on Windows.
   - Replace `<log>` with a log file path.
   ```bash
   SEP=':'; [[ "$OS" == "Windows_NT" ]] && SEP=';'
   env 'keycloak-external-url=http://localhost:8083' 'db-server=localhost' 'db-port=5456' \
       'postgres-password=mosip123' 'mosip_components_base_urls=' \
     java -Dmodules=masterdata -Denv.user=api-internal.local -Denv.endpoint=http://localhost:8083 \
       -Denv.testLevel=smokeAndRegression -cp "target/classes${SEP}$(cat target/cp.txt)" \
       io.mosip.testrig.apirig.masterdata.testrunner.MosipTestRunner > <log> 2>&1 &
   ```
   Wait for the process to exit (a full masterdata run takes a few minutes).
4. **Read the results:** the newest `testng-report/*-<lang>-*-full-report_T-…_P-…_S-…_F-…_I-…_KI-….html` per language; the counts are in the file name. Report a T/P/S/F/I/KI table per language and analyse only failed and skipped tests. On a freshly wiped database, 2 eng failures are expected (see "Do").
5. **Set the gateway back to 8086** and reload WireMock.

### 6. Clean up

- Stop only the process you started (8096).
- Restore anything you changed temporarily, such as the gateway port.
- Leave the containers and the user's 8086 app running.

### Config-only changes

| Changed file | What to restart |
|---|---|
| `deps/mosip-config/admin-local.properties` | Your 8096 instance (step 3), then step 4 |
| `deps/mosip-config/keymanager-local.properties` | `docker compose -f deps/docker-compose.yml restart keymanager`, wait for `healthy`, then step 4 |

## Do

- Read the folder's `README.md` before changing or refreshing it (`deps/mosip-config`, `deps/mosip-data`, `deps/keymanager`, `deps/wiremock`, `tools/jwt`): contents, rules, refresh steps, versions in use. Update the versions there after a refresh.
- Edit only this tree. Put local config in the service's own overlay: `admin-local.properties` or `keymanager-local.properties`.
- Change a value the config server serves in the overlay. The app uses bootstrap config, so config-server values override `-D` flags; only keys no served file sets (`server.port`, `spring.cloud.config.uri`) work as `-D`.
- Users, clients and roles: edit `tools/jwt/tokens.properties`, then run `tokens`. Commit `keycloak-authmanager.json` only together with that change. A run that created a new key re-signs every token: restart admin-service.
- Keep the JWT issuer `http://localhost:8083/auth/realms/mosip`.
- WireMock stubs: put a stub in the file of the caller that sends the request; check priorities across all three mapping files first (catch-alls stay at 10); reload with POST `/__admin/mappings/reset`.
- Reset the database and the keystore only with `wipe` (both volumes in one step). Keep `keymanager-keys-init` as keymanager's dependency: it hands the keystore volume to uid 1001.
- Pin every image to a version. Keep the keymanager image tag and its `db_scripts` tag the same.
- Keep `run-local-stack.sh` and `run-local-stack.bat` in step: same commands, ports and checks. `.sh` stays LF, `.bat` CRLF (`.gitattributes`).
- The IDE keeps port 8086; a second instance uses 8096 (`run 8096`, `smoke 8096`). If the rig gateway is pointed at another port, set it back to 8086 before committing.
- API test rig: expect 2 eng failures on the first run against a fresh DB (`Admin_GetMachineHistory_allValid_smoke`, `MasterData_GetUserDetailsByIdAndEffDate_allValid_smoke`); see `README.md`.

## Don't

- Edit the verbatim copies: `*-default` files, `identity-mapping.json`, `applicanttype.mvel`, `deps/mosip-data/xlsx`, `deps/keymanager/db_scripts`. Refresh them by copying from the source repo.
- Add `kernel-local` or `application-local` overlays: they would apply to every service and beat `admin-default`.
- Change `admin-services/db_scripts` to make the local stack work: they are the real DB scripts for every environment.
- Hand-edit `keycloak-authmanager.json`, or commit `keys/jwt-signing-key.pem`.
- Run `tokens` after a clone, `up`, `down` or `wipe`: the committed JSON already has the tokens.
- Remove one of the two volumes alone (`docker volume rm`), or run `down -v` unless you want a full reset.
- Use `latest` or `develop` image tags.
- Seed data or add stubs to hide the 2 expected first-run failures.
- Run the app in Compose, use `{cipher}` values, copy tokens or secrets from a real environment, or add the auth adapter to the keymanager container.

## Troubleshooting

Full steps for each row: `README.md`, "Troubleshooting". `wipe` deletes the database and the keys, so an agent asks the user before running it.

| Symptom | Cause | Fix |
|---|---|---|
| App: `Connection refused` on `localhost:51000` | `-Dspring.cloud.config.uri` missing | Add `-Dspring.cloud.config.uri=http://localhost:51200/config`, restart the app |
| App: `Could not resolve placeholder 'x'` | `x` missing from the overlay | Add it to `admin-local.properties`, restart the app |
| App: `No servers available for service: localhost` | `local` profile not active, so `spring.cloud.loadbalancer.enabled=false` is missing | Use `-Dspring.profiles.active=default,local`, restart the app |
| App: `Port 8086 was already in use` | Another instance is running | Stop it, or use `run 8096` |
| API returns 401 with a token | The app holds an old JWKS | Reload WireMock (`mappings/reset`), restart the app, get a new token |
| `tokens`: `AccessDeniedException: keys` | `keys/` not writable by you | `chown` `keys/` to your user, run `tokens` again |
| WireMock returns 404 | No stub for the call | Add one: `admin-services.json` (app calls) or `api-test-rig.json` (rig calls) |
| wiremock `exited`, `MappingFileException` | A mapping file is not valid JSON | Fix the file, `up` |
| `port is already allocated` | 5456, 51200, 8083 or 8089 used by another process or stack | Stop that process or container, `up` |
| postgres `exited` on the first `up` | `init.sql` or a `db_scripts` file failed | `logs postgres`, fix the file, then `wipe` (ask the user first) |
| config-server `unhealthy` | Slow start (Docker short of CPU or memory) | `up` again |
| `keymanager-bootstrap: ERROR: keymanager exited` | Value missing from `keymanager-local.properties`, or `mosip_keymgr` unreachable | Add the value or check postgres, restart keymanager |
| `keymanager-bootstrap: ERROR: {...KER-KMA...}` | Keystore and database out of step | `wipe` (ask the user first) |
| `keymanager-keys-init` did not complete, or keystore `Permission denied` | Keystore volume not owned by uid 1001 | Run `keymanager-keys-init`, restart keymanager |
| `keymanager-bootstrap: ERROR: KERNEL:SIGN certificate not available` | Keys created but cannot be read back | `wipe` (ask the user first) |
| `keymanager-bootstrap: ERROR: health timeout` | Docker short of CPU or memory, or config-server down | Check config-server and `docker stats`, restart keymanager |
| `smoke`: sample test data `[FAIL]` | The loader failed or did not run | Run the loader again (`docker compose -f deps/docker-compose.yml --profile seed run --rm masterdata-loader`); still failing: `wipe` (ask the user first) |
